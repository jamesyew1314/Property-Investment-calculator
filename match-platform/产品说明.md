# 智能房源配对 · 产品说明（v0.1）

> 给老板 / 合伙人的一页版：这是什么、怎么帮代理赚钱、现在做到哪、下一步做什么。  
> 试用：`cd match-platform && node server.js` → <http://127.0.0.1:4100>（演示账号 `demo@propmatch.my` / `demo1234`，或直接打开 `/?demo=1`）

---

## 一、一句话

**把客户需求与房源放进同一个工作台，系统按六个维度打分并解释“为什么适合”，代理照着名单联系即可。**

不是另一个房产门户，也不是通用 CRM；它解决的是中介每天最花时间、最容易漏的一步：**把对的房子找给对的人**。

---

## 二、代理现在的痛点

| 痛点 | 现实 |
| :--- | :--- |
| 需求散 | 客户在 WhatsApp 说“80 万、四房、Austin 区、最好有保安”，三天后只剩模糊记忆 |
| 盘源多 | 自己 + co-broke + 开发商，几十上百间，靠 Excel/记忆配对 |
| 算不清 | 客户说预算 80 万，但没算过收入能贷多少、现金够不够首付与律师费 |
| 说不清 | 推荐了，客户问“为什么是这间”，只能说“这个不错” |
| 卖家常问 | “我的房有人要吗？”代理只能凭感觉回答，无法拿出客户名单 |
| 跟进断 | 推荐后没有状态、没有漏斗、没有“该再联系谁” |

## 三、系统怎么解决（对应到界面）

### 1. 录一次需求（约 30 秒）

客户称呼、买/租、预算上下限、区域、房型、房间/面积、产权/装修、必备/加分/避雷、时间表；可选填收入/负债/现金。

- 表单里直接显示「按此资料，可负担约 RM X」；
- 客户说“预算 80 万”，系统会告诉你：按 65% DSR、4.3%、30 年、90% 贷款、现金 18 万，其实可负担约 **107.6 万**——预算保守，可以看更高价位；或者反过来，预算超了，需要增加现金/担保人。

### 2. 工作台「今日优先配对」

按 `匹配分 + 客户紧迫度 + 跟进到期` 排序，每个需求最多两条；卡片直接写两三条理由：

- “在预算内，余 RM 70,000（8.2%）”
- “同区群：Austin Heights（距 Mount Austin 约 1.8 km）”
- “4 房（需求 4+）· 永久产权 · 近学校/围篱”
- “刚好在预算上限，议价空间小”

点分数环可看六个维度、权重、加分/扣分、资料缺口——**每个分数都能解释，不是黑盒**。

### 3. 一键发 WhatsApp

自动生成中/英推荐文案：房源摘要 + 匹配点 + 注意事项 + 公司/REN/电话 + 免责声明。代理复制或打开 `wa.me`，不自动群发，避免被平台判定骚扰。

### 4. 跟进漏斗

收藏 → 已推荐 → 已看房 → 已出价 → 成交/未成交/不合适；写备注；工作台实时显示漏斗与待跟进（逾期标红）。

### 5. 卖家视角：一间房倒推客户

打开房源详情 → 「适合的客户」按需求反向评分，附预算、可负担性、匹配理由。  
卖家问“有人要吗”，代理可以直接拿出名单：“这 3 位客户预算与区域都合适，其中 2 位已看房。”

### 6. 房源分析（与投资计算器同口径）

每间房自动算：预估月供、首付、SPA/LA 律师费与印花税、估价费、SST、所需现金、每平方尺价、同区参考。  
客户问“买了每月要还多少”，不需要再开一个计算器。

## 四、和竞品/现有工具的区别

| 对比 | 房产门户（PropertyGuru 等） | 通用 CRM | **PropMatch** |
| :--- | :--- | :--- | :--- |
| 核心 | 买卖流量 | 流程管理 | **配对 + 解释 + 可负担性** |
| 客户需求 | 表单筛选 | 自由文本 | 结构化 + 可解释评分 |
| 房源 | 海量挂牌 | 无 | 自有 + co-broke 盘源 |
| 算钱 | 无/简单 | 无 | 复用马来西亚法定费用与贷款公式 |
| 卖家视角 | 无 | 无 | **一间房倒推买家名单** |
| 录入成本 | 高 | 高（中介不愿填） | 30 秒；后续接 WhatsApp/语音抽需求 |

**定位**：不做“另一个门户”，做中介每天打开的「配对工作台」。等盘源与成交数据积累后，再考虑 co-broke 交换所与参考价（AVM 区间，不叫估值）。

## 五、现在做到哪（v0.1，可演示）

✅ 已完成：

- 需求/房源完整 CRUD，买家 + 租客 + 卖家；
- 六维可解释配对、硬门槛、近似匹配、资料完整度、四种优先级档案；
- 今日优先、反向配对、跟进漏斗、待跟进；
- 可负担性（收入/DSR/现金）、买入成本、月供、同区参考；
- 中/英双语、手机适配、图片查看、WhatsApp 文案、JSON 导出；
- 账号注册/登录/改密（旧会话撤销）、数据隔离；
- **51 项自动化测试全过**；与投资计算器的 canonical 数字对齐（76,630 / 18,767 / 656,337.29 / 1,076,000）。

⏳ 未做（有意控制范围）：

- 自动 WhatsApp 发送、邮件/短信提醒；
- 团队角色与佣金账本；
- 门户/CSV 批量导入、照片上传；
- 客户只读分享页、电子签、付款；
- 马来语 UI、原生 App；
- 公开注册/计费（当前先内部使用）。

## 六、怎么衡量有没有用（建议 KPI）

| 指标 | 定义 | 目标（试用 4 周） |
| :--- | :--- | :--- |
| 需求录入率 | 新增客户是否 24h 内录入 | ≥ 80% |
| 首推时间 | 需求创建 → 第一次「已推荐」 | < 10 分钟 |
| 推荐→看房 | 已推荐中进入已看房的比例 | ≥ 25% |
| 看房→出价 | 已看房进入已出价的比例 | ≥ 20% |
| 资料完整度 | 需求/房源关键字段覆盖 | 平均 ≥ 70% |
| 每周活跃 | 每周至少打开 3 天的代理 | ≥ 70% |
| 卖家响应 | 房源详情有反向客户名单的比例 | ≥ 60% |

> 如果 4 周后「推荐→看房」没有提升，说明问题不在配对，而在房源质量/价格/回复速度；到时再决定是否加 WhatsApp 自动化。

## 七、商业化路径（与既有 SaaS 方案一致）

1. **内部先用**（THE ROOF / 自己和合伙人）：0 成本，验证工作流与话术；
2. **团队版**：RM 199–499/月，含多代理、团队看板、盘源共享、佣金记录；
3. **个人版**：RM 49–99/月，配对 + 可负担性 + WhatsApp 文案；
4. **co-broke / 白标**：给代理公司做自有盘源 + 客户分析页，收项目费/年费；
5. **数据飞轮**：真实成交/租金回流，形成 comps 与参考价区间（不对外叫 AVM）。

**不建议**：做公开房产门户、通用 CRM、独立电子签、通用 AVM——获客成本与合规成本都不划算。

## 八、下一步（等拍板）

| 优先级 | 事项 | 预计 | 为什么 |
| :--- | :--- | :--- | :--- |
| P0 | 真实试用：你和 2–3 位代理录入 20 组真实需求 + 30 间房，跑 2 周 | 即刻 | 验证分数是否“像人话”、哪一维最常误判 |

| P2 | CSV/门户导入、照片上传、客户只读分享页 | 2–3 周 | 降低录入成本、提升专业度 |

**需要你确认的 3 件事**

1. 先用**真实数据**跑 2 周，还是先补 WhatsApp 自动发送？
2. 团队版是否要**佣金/分账**（这会把它从配对工具变成 CRM，工作量 +1–2 周）？
3. 是否要把「配对」接到现有**投资计算器/视频平台**的客户账号体系（统一登录，还是先独立）？

## 九、风险与对策

| 风险 | 对策 |
| :--- | :--- |
| 代理不愿录入 | 30 秒表单 + 先只填 5 个必填；后续 WhatsApp/语音抽取需求 |
| 分数不被信任 | 每个分数可展开原因；不承诺“保证成交”；显示资料完整度与免责声明 |
| 数据太旧/假盘 | 房源状态、委托到期、更新日期；co-broke 验证机制（后续） |
| 客户隐私（PDPA） | 账号隔离、导出/删除权、备注禁存敏感个资、HTTPS |
| 单人依赖 | 公式与权重写进代码/测试；文档 + 部署脚本；不靠某个人的记忆 |
| 过度承诺估值 | 只做“参考价区间/同区挂牌参考”，不叫 valuation，不替代持牌估值师 |
