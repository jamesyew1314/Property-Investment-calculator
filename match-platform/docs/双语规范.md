# PropMatch 中英双语规范

> **强制要求：所有页面、所有状态、所有用户可见文案都必须中英双语。**  
> 不是“首页双语”或“主要页面双语”，而是登录、工作台、需求、房源、配对、设置、表单、弹窗、空状态、错误、加载、移动端、PWA、页面标题，以及 WhatsApp / 邮件文案，全部覆盖。  
> 最后更新：2026-10-27 · 适用版本：v0.1+

---

## 1. 范围（哪些算“页面”）

必须双语的地方：

| 类别 | 例子 |
| :--- | :--- |
| 页面 | 登录 / 注册、工作台、客户需求列表与详情、房源列表与详情、配对中心、设置与说明 |
| 状态 | 加载中、空列表、无匹配、无近似、无动态、未登录、404/错误页 |
| 表单 | 所有字段标签、占位符、提示、必填星号、字段级错误、保存中、保存成功/失败 |
| 弹窗 | 评分明细、跟进、WhatsApp 文案、账号资料、修改密码、图片预览、删除确认 |
| 组件 | 按钮、标签、筛选器、下拉选项、评分环、资料完整度、徽章、tooltip、aria-label |
| 移动端 | 底部导航、手机版表单、手机版详情、手机版弹窗 |
| 浏览器/系统 | `document.title`、`<html lang>`、PWA manifest、静态 loading/noscript |
| 服务端错误 | 登录失败、注册重复、字段校验、权限、限流、服务器错误（页面会显示这些文案） |
| 对外文案 | WhatsApp 推荐文案、邮件主题/正文、分享文案 |

**不翻译（例外）**

- 用户自己输入的资料：客户姓名、备注、地址、自定义标题等，按原文显示；
- 法定名称/品牌：`THE ROOF REALTY SDN BHD`、`KWONG THYE 光泰`、`REN 32839`、`E(1)1605/1`、人名；
- 金额、日期、电话号码、单位（`RM`、`sqft`）按语言格式化，但不改数字；
- 第三方内容（门户导入/客户发来的原文）。

## 2. 现有实现

| 层 | 文件 | 作用 |
| :--- | :--- | :--- |
| 字典 | `public/i18n.js` | 单一 `S(zh, en)` 表，当前 **587 个键**；`makeT(lang)` 返回 `t(key, params)` |
| 页面 | `public/views.js` | 所有页面用 `ctx.t(key)`；禁止直接写用户可见中文/英文 |
| 表单/弹窗 | `public/forms.js` | 同上；网络失败兜底也走 `tr(zh, en)` |
| 通用组件 | `public/ui.js` | 图标、评分环、确认框、月份名等按 `lang` 输出 |
| 数据字典 | `lib/taxonomy.js` | 区域/房型/产权/标签/状态等全部带 `zh` + `en`，经 `/api/meta` 下发 |
| 引擎文案 | `lib/engine.js` | 只输出 **原因代码**（如 `budget.within`），不写死文案；前端 `format.js` 翻译 |
| 格式化 | `public/format.js` | 金额、日期、标签、原因/失败/缺失文案、WhatsApp 文案 |
| 服务端错误 | `lib/error-i18n.js` | 根据 `Accept-Language: en` 翻译 API 错误与字段错误 |
| 静态壳 | `public/index.html` | loading / noscript / 页面标题本身双语 |
| PWA | `public/manifest.webmanifest` | name/description 双语 |

### 语言切换链路

1. 用户点 `EN / 中文` → 写入 `localStorage["kwongthye_lang"]`；
2. `app.js` 重新渲染，`ctx.lang` 变为 `en` / `zh`；
3. 所有 `ctx.t(key)` 取对应语言；`<html lang>` 与 `document.title` 同步；
4. API 请求带 `Accept-Language`，服务端错误用同一语言返回；
5. 刷新后从 `localStorage` 恢复，不需要重新登录。

## 3. 开发规则（必须遵守）

1. **禁止硬编码用户可见文案。**  
   新页面/按钮/提示必须加到 `public/i18n.js`，使用 `ctx.t('key')`。  
   允许的硬编码只有：品牌名、法定名称、URL、金额/数字本身。

2. **每个键必须同时有中文和英文。**  
   `S('中文', 'English')` 两个值都不能为空；参数占位符（`{n}`、`{name}`）两边必须一致。  
   `test/i18n.test.js` 会检查键集合、空值和引擎原因码覆盖。

3. **新增页面必须做双语验收。**  
   在中文和 English 下分别检查：页面标题、导航、空状态、表单、弹窗、错误提示、手机 390px。  
   不能只看首页；必须逐页切换语言。

4. **服务端错误也要双语。**  
   新增中文错误提示时，同步在 `lib/error-i18n.js` 补英文；前端 `api()` 已自动发送 `Accept-Language`。  
   字段级错误（`fields`）同样要走映射，不能只翻译顶层 `message`。

5. **引擎/业务层不写文案。**  
   新增原因、失败、缺失提示时：  
   - 在 `lib/engine.js` 增加代码（如 `fit.new`）；  
   - 在 `NOTE_CODES` / `FAILURE_CODES` / `MISSING_CODES` 注册；  
   - 在 `public/i18n.js` 加 `note.*` / `failure.*` / `missing.*` 中英文；  
   - 测试会自动拦截缺键。

6. **静态壳也要双语。**  
   `public/index.html` 的 loading、noscript、meta 文案必须中英并列；PWA manifest 的 name/description 也要双语。

7. **日期/金额/单位按语言格式化。**  
   用 `format.js` 的 `fmtMoney`、`fmtDate`、`fmtPct`、`budgetText`，不要手写 `RM` 或 `年/月`。

8. **用户数据不翻译。**  
   客户备注、地址、自定义标题按原文显示；但如果数据模型有 `title_en` 等英文字段，页面在 English 下优先显示英文字段。

## 4. 新增一个页面/模块的检查清单

- [ ] 路由与导航名称已加 `nav.*` 中英键
- [ ] 页面标题已加 `page.*` 或使用 `nav.*`，`document.title` 随语言变化
- [ ] 页面所有按钮、标签、空状态、加载、错误都有 `ctx.t`
- [ ] 表单字段标签、占位符、字段错误都有中英
- [ ] 弹窗标题、按钮、确认文案都有中英
- [ ] 移动端底部导航/布局在两种语言下不溢出
- [ ] 服务端新增错误已在 `lib/error-i18n.js` 补英文
- [ ] `node --test test/i18n.test.js` 通过
- [ ] 中文/English 各截图一次（1440px + 390px）
- [ ] 刷新后语言保持；登录/退出后仍保持

## 5. 验收命令

```bash
cd match-platform

# 字典键一致、无空值、引擎原因码全覆盖
node --test test/i18n.test.js

# 全量回归（含 API 英文错误）
npm test
```

手工验收（每页都要做）：

1. 打开 `https://match.kwongthye.com/`，切到 English；
2. 逐页检查：登录 → 工作台 → 客户需求 → 需求详情 → 房源库 → 房源详情 → 配对中心 → 设置；
3. 打开评分明细、跟进、WhatsApp、编辑资料、修改密码、删除确认、图片预览；
4. 提交空表单，确认客户端与服务端错误都是英文；
5. 手机 390px 重复以上关键页面；
6. 切回中文，确认没有残留英文；
7. 刷新页面，确认语言保持。
