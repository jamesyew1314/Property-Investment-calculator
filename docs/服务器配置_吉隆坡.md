## 7. 备份与恢复

**每日备份**（02:15）：

```bash
/srv/fangchan/backups/backup.sh
# 产物：fangchan-YYYY-MM-DD.dump + .dump.sha256
```

**异地备份**（02:40）：`/srv/fangchan/ops/offsite-backup.sh`（ossutil 上传，配置在 `/root/.ossutilconfig`）。

**恢复演练**：每月 1 日 03:30 自动跑 `restore-drill.sh`，日志 `logs/restore-drill.log`。

手动恢复示例：

```bash
sudo -u postgres createdb fangchan_restore
sudo -u postgres pg_restore -d fangchan_restore /srv/fangchan/backups/fangchan-YYYY-MM-DD.dump
```

## 8. 部署流程

```bash
# 本机（仓库根目录）
bash deploy/deploy.sh
```

脚本会：

1. 跑测试（计算器 76、资料库 69、工作台 9、计费 8）

3. scp 后端 JS 到 `/srv/fangchan/api`
4. `systemctl restart fangchan-api`
5. 健康检查 `/api/health`

回滚：重新部署上一个 git tag（`git checkout vX.Y` 后重跑 deploy）。

## 10. 安全现状与建议

**已做：**

- PostgreSQL 只监听 `127.0.0.1`
- API 只监听 `127.0.0.1:3000`，公网只开 80/443
- 密钥集中在 `/srv/fangchan/api/.env`（权限 600，属主 `fangchan`）
- OSS 配置仅 root 可读
- 证书自动续期；每日备份 + 异地备份 + 月度恢复演练
- ufw 已启用

**需要处理：**

| 优先级 | 项 | 说明 |
| :---: | :--- | :--- |
| 高 | `8787/tcp` 对公网开放 | 未确认用途，建议核实后 `ufw delete allow 8787/tcp` |
| 高 | `3100/tcp` 对公网开放 | PropReel 应只走 nginx 反代，建议关闭直连 |
| 中 | SSH 端口 22 对全网开放 | 建议限制来源 IP，或改用非标端口 + fail2ban |
| 中 | 单机无冗余 | 数据库与应用同机；规模上来后先升配，再考虑只读副本 |
| 低 | 上传目录未上 CDN | 目前 32 KB，量起来后再接 OSS/CDN |

## 11. 容量评估

| 指标 | 现状 | 建议阈值 |
| :--- | :--- | :--- |
| 磁盘 | 9.2 / 40 GB | 到 70% 升盘或清日志 |
| 内存 | 951 MiB / 3.5 GiB | 到 80% 升配（4C8G） |
| 数据库 | 10 MB | 1 GB 以内单机足够 |
| 图片 | 32 KB | 按每条房源 5 张 × 200 KB 估算 |

**结论：当前配置足够支撑 100–300 位中介、几千条房源。**  
到 1,000 位中介或图片量明显上来时，优先：升 4C8G → 图片转 OSS+CDN → 数据库只读副本。
