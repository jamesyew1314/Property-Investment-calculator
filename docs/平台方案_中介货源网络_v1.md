> 日期：2026-10-27 · 状态：**分析稿，等你拍板**  
> 一句话：把「中介手上的 WTS 货源 / WTB 客源」变成一张**可搜索、可归因、可收费**的网络，每个中介有自己的工作台和个人站。

## 0. 结论（先看这一页）

| # | 结论 | 依据 |
| :---: | :--- | :--- |
| 1 | **是 SaaS，但不是普通 SaaS。** 交付方式是多租户 SaaS（按席位订阅），但产品本质是「**垂直行业网络 + 个人工作台**」。只做软件（工具）不会有粘性；只做群（信息流）不能收费。两者必须合在一起。 | 见 §2 |
| 2 | **80 人不是负担，是冷启动资产。** 一个网络最怕没人发；你有 80 个现成中介，先让 20 个活跃，池子就转起来了。 | 见 §8 |
| 3 | **数据量很小，不是「大数据」。** 80 人 × 60 条房源 ≈ 4,800 条 + 图片 ≈ 10GB；现在 2C4G 的服务器完全够，基础设施 **RM 200–500/月**。 | 见 §6.1 |
| 4 | **真正的成本是运营和习惯养成，不是服务器。** 人力约 **RM 4,000–5,000/月**（半个运营 + 少量开发维护）。 | 见 §6.2 |
| 5 | **只做内部 80 人，收入刚好覆盖成本，不是利润中心。** 80 席 × RM69 ≈ RM5,500/月，减基础设施与人力所剩无几；利润来自**复制到别的团队**（EAG 18k 中介是池子）。 | 见 §7.2 |
| 6 | **MVP 3–4 周可上线**：多租户 + 中心池 + 个人站 + 一键分享 + 计算器，全部能在现有系统上加，不用重写。 | 见 §10 |

**建议先做**：中心池 + 个人工作台 + 一键分享（MVP），**内部 90 天免费**换使用习惯，第 91 天起 RM 39–69/月早鸟价；对外标准价 RM 99/月。

## 1. 需求还原

### 1.1 你描述的业务

> 「中介手上有两种人：WTB（买家，委托找房）、WTS（卖家，委托卖房）。做一个平台，让他们把资料放进来给大家找。每个人一个账户，里面有个人信息、计算器、自己的货源和买家资料；这些资料自动连到中心的 listing group 和 WhatsApp group。团队 80 人。」

翻译成产品语言：

| 角色 | 他们要什么 | 平台给什么 |
| :--- | :--- | :--- |
| **中介（核心用户）** | 更多货源被看见、更多买家来问、自己的专业形象、少做重复劳动 | 个人工作台 + 个人站 + 一键同步到中心池 + 询盘 |
| **货源方（WTS 的中介）** | 房子快点卖掉、不被飞单 | 曝光 + 归因（谁带来的客）+ 带看记录 |
| **客源方（WTB 的中介）** | 快速找到匹配的盘 | 搜索/筛选 + 配对 + 直接联系货源方 |
| **团队长/公司** | 管理、数据、品牌 | 团队看板 + 账号管理 + 成交归因 |
| **买家/卖家（终端）** | 找到专业中介 | 个人站 + 房源页（SEO/分享） |

### 1.2 现在怎么做，卡在哪

| 现在 | 问题 |
| :--- | :--- |
| WhatsApp 群发房源图 | 不能搜索、刷屏、过期信息、新人看不到历史、**不知道是谁的盘** |
| Excel / 备忘录记客户 | 离职就带走、多人不能协作、忘记跟进 |
| 口头/群里问「有没有 XX 区的盘」 | 靠人情，效率低，重复问 |
| 个人 Facebook 页 | 有品牌但没结构，不能筛选，不能归因 |

**核心矛盾**：信息在群里流动，但**群不是数据库**；软件能存数据，但**中介不会每天登录**。谁能同时解决「流动」和「沉淀」，谁就赢。

## 2. 这是不是所谓的 SaaS？

### 2.1 交付方式：是

- 多租户（一个中介一个 workspace）
- 按席位/按月订阅
- 浏览器即用，无需安装
- 版本持续更新

这几条就是标准 SaaS。

### 2.2 但本质不是「软件」，是「网络」

普通 SaaS（比如会计软件）价值 = 功能。  
你这个平台的价值 = **池子里有多少货、多少人来看**。功能只是入口。

用三个词定性更准确：

| 形态 | 是什么 | 能否收费 | 问题 |
| :--- | :--- | :--- | :--- |
| **工具**（只做个人库+计算器） | 个人 CRM | 能，但便宜（RM 20–30/月），替代品多 | 没有网络效应，中介走了数据也走了 |
| **信息流**（只做 WhatsApp 群） | 群发 | 不能 | 不可搜索、不可归因、会刷屏、会封号 |
| **网络 + 工作台**（本方案） | 中心池 + 个人库 + 分发 | 能，且可以溢价 | 冷启动难，需要运营 |

**结论：是 SaaS 的收费方式 + 市场的网络效应。** 行业里叫 **Vertical SaaS + B2B Marketplace**（垂直行业 SaaS + 同业交易网络）。

### 2.3 为什么不能只做一半

- 只做工具：中介凭什么每天登录？他没有「必须来」的理由。
- 只做池：谁都可以看，谁都不贡献；没有个人库，中介不会把客户资料放进来。
- **必须让「发布」有即时回报**：发一条房源 → 立刻生成个人站页面 + 分享卡片 + 进中心池 → 当天可能有同行来问。这个闭环是留存的关键。

## 3. 产品结构（三层）

```
┌─────────────────────────────────────────────┐
│  L0 中心站  kwongthye.com/network           │
│  全网房源池 · 客源池 · 每日精选 · 搜索       │
└───────────────▲─────────────────────────────┘
                │ 一键发布（可选公开/仅池内）
┌───────────────┴─────────────┐   ┌──────────────────────┐
│  L2 个人工作台 /app          │   │  L1 个人站 /a/andy   │
│  我的房源 · 我的 WTB · 计算器 │──▶│  个人品牌页 + 在售   │
│  分享 · 询盘 · 数据          │   │  SEO + WhatsApp 入口 │
└─────────────────────────────┘   └──────────────────────┘
```

### 3.1 L0 中心站（网络的门面）

- 房源池：按区域/价位/房型/面积筛选，卡片显示「**货源：Andy Lau · REN 32839**」
- 客源池（WTB）：只对登录中介可见（客户隐私），显示预算/区域/时间表，联系方式走平台
- 每日精选：早上 9 点一封邮件/一条群消息「今天 12 条新货」
- 公开部分：区域页、楼盘页做 SEO，吸引自然流量 → 引导注册

### 3.2 L1 个人站（每个中介一张名片）

- `kwongthye.com/a/<slug>`（先用路径，不用子域，省证书、SEO 集中）
- 内容：头像/简介/REN/电话/WhatsApp、在售房源、成交案例、计算器入口
- 一键分享给买家；买家点「咨询」→ 落到该中介的询盘
- 以后可升级自定义域名（`andylau.com`）作为高级档

### 3.3 L2 个人工作台（每天要来的地方）

| 模块 | 内容 |
| :--- | :--- |
| 我的房源 | 增删改、状态、图片、一键发布到中心池 |
| 我的 WTB | 买家需求、预算、跟进状态 |
| 计算器 | 现有投资计算器，带房源价格预填（已打通） |
| 分享 | 一键生成 WhatsApp 卡片/文案、复制链接 |
| 询盘 | 谁看了、谁问了、谁要带看 |
| 数据 | 曝光、询盘、成交（简单版） |

### 3.4 权限矩阵

| 能力 | 免费 Pool | Pro 个人 | 团队 Agency |
| :--- | :---: | :---: | :---: |
| 看中心池 | ✅ | ✅ | ✅ |
| 发布到中心池 | ✅（最多 5 条在售） | ✅ 不限 | ✅ 不限 |
| 个人数据库（房源+WTB） | ❌ | ✅ | ✅ |
| 个人站 `/a/xxx` | ❌（只显示公司页） | ✅ | ✅ |
| 计算器 | ✅ 基础 | ✅ 完整 + PDF | ✅ |
| 分享卡片 | 文字 | ✅ 图片卡片 | ✅ 品牌定制 |
| 询盘/归因 | 仅站内 | ✅ | ✅ + 团队看板 |
| 团队管理/分账号 | ❌ | ❌ | ✅（5 席起） |
| 数据导出 | ❌ | 限 200 条/月 | ✅ |

## 4. 核心机制

### 4.1 发布只要 30 秒

中介最怕填表。做法：

1. 选楼盘（已有字典）→ 自动带出区域/房型/产权
2. 填 3 个数：单位号、面积、价格
3. 拍照/选图 → 自动压缩
4. 点「发布」→ 同时生成：个人站页面、WhatsApp 卡片、中心池条目

后续可加 AI 解析：「Sutera Utama 3房 1150sqft 卖 72万」一句话生成草稿。

### 4.2 中心池的规则（防止垃圾）

- 必须有：区域、价格、至少 1 张图、有效联系电话
- 同一单位只能有一条（数据库唯一索引，已实现）
- 30 天未更新自动标「待确认」，60 天归档
- 发布人显示姓名 + REN（建立信任，也防飞单）

### 4.3 分发：不要只靠 WhatsApp 群

| 渠道 | 做法 | 风险 |
| :--- | :--- | :--- |
| **站内池** | 登录可见，可搜索 | 无 |
| **每日邮件** | 9:00 汇总「新货 + 急售」 | 无 |
| **WhatsApp 手动分享** | 生成卡片图 + 文案，中介点一下发到自己的群 | 无（推荐主力） |
| **WhatsApp 官方 API** | 订阅者自动收 | 按条计费、要 WABA 认证、模板审核 |
| **非官方群机器人** | 自动发群 | ⚠️ **封号风险高，不建议** |

**建议**：第一版只做「生成 + 一键分享」，不做机器人。等有 100+ 活跃再上官方 API 做「每日精选订阅」。

### 4.4 归因与防飞单（这是能不能收费的关键）

- 每条房源有编号 `KT-1234` + 货源中介
- 池内卡片永远显示「货源：谁」
- 同行点「我要带客看房」→ 生成一条 **lead 记录**（谁、什么时候、哪条盘）
- 货源方收到通知；成交后可在系统登记「合作成交」
- 规则写进用户协议：**默认合作佣金 50/50 或双方约定，平台留痕**
- 平台不碰佣金资金（避免金融合规），只做记录

> 没有归因，中介不会把好盘放进来——因为他怕被抢。归因是网络的信任基础。

### 4.5 WTB 客源池

- 买家需求默认**只显示尾号**，完整联系方式只给需求方
- 匹配：复用 `match-platform` 的六维引擎（区域/预算/房型/面积/装修/时间）
- 双向：房源找买家、买家找房源
- 隐私：录入时必须勾选「已获客户同意用于配对」（PDPA）

## 5. 复用现有资产 & 改造清单

| 能力 | 现在有什么 | 要改什么 | 工作量 |
| :--- | :--- | :--- | :--- |
| 账号/登录 | 后台账号 + 邮件验证码；客户账号体系 | 加 `agent` 角色、套餐字段、个人 slug | 2–3 天 |

| 个人站 | 企业站 + 品牌 | `/a/<slug>` 模板、SEO、JSON-LD | 3–4 天 |
| 计算器 | 已上线，支持 `?d=` 预填 | 个人站入口 + 品牌化 | 0.5 天 |

## 7. 定价

### 7.1 三档（建议）

| 档位 | 价格 | 给谁 | 包含 |
| :--- | ---: | :--- | :--- |
| **Pool 免费** | RM 0 | 观望的人、兼职 | 看池 + 发 5 条在售 + 基础计算器；无个人库/个人站；联系方式走平台 |
| **Pro 个人** | **RM 69/月**（年付 RM 690） | 全职中介（主力） | 个人库无限 + 个人站 + 完整计算器/PDF + 图片卡片 + 询盘 + 数据 |
| **Agency 团队** | **RM 249/月**（5 席，+RM 45/席） | 小团队/公司 | Pro 全部 + 团队看板 + 品牌定制 + 分配 + 导出 |

### 7.2 三种转化率的收入模型

| 场景 | 付费席 | MRR | 减成本后 |
| :--- | ---: | ---: | ---: |
| 保守（25%） | 20 | RM 1,380 | −3,700（需补贴） |
| 中性（50%） | 40 | RM 2,760 | −2,300 |
| 乐观（80%） | 64 | RM 4,416 | −600 |
| **全 Pro + 5 个团队档** | 80 + 5×249 | RM 6,765 | +1,700 |
| **对外 200 Pro + 20 团队** | 200 + 20×249 | RM 18,780 | +13,700 |

> 内部阶段不要指望赚钱，目标是**跑通留存与归因**；对外复制才是生意。

### 7.3 为什么这样定

- **锚定成交**：一单佣金 RM 5,000–20,000；RM 69 = 1.4% 的一单，心理门槛低。
- **免费档不是慈善**：它保证池子有货（网络密度），但拿不走数据（无个人库、无导出）——这是付费的真正理由。
- **不按数据量收费**：中介听不懂，也会怕；按「席位 + 功能」最简单。
- **年付打折**：现金流前置，退订率下降。

### 7.4 早鸟与团队方案

- **内部 80 人：90 天全功能免费**（换反馈 + 案例）
- 第 91 天：**RM 39/月锁 24 个月**（早鸟），之后恢复 RM 69
- 推荐奖励：成功推荐 1 人付费 → 免 1 个月
- 团队档：5 席起，第 6 席 RM 45

## 8. 冷启动 90 天（习惯养成，这是重点）

### 8.1 为什么难

中介不缺工具，缺**每天打开的理由**。所以前 90 天不是做功能，是**做习惯**。

### 8.2 具体动作

| 周 | 动作 | 目标 |
| :--- | :--- | :--- |
| W1–2 | 20 个种子中介 1 对 1 开通，帮他们录前 3 条房源 | 60 条真实货源 |
| W3–4 | 每天 9:00「今日新货」邮件 + 群卡片；每周榜 | 日活 30% |
| W5–6 | 上线 WTB 池 + 配对；第一个「池内合作成交」案例 | 首个归因成交 |
| W7–8 | 个人站分享比赛（谁的个人站带来最多咨询） | 每人至少分享 1 次 |
| W9–10 | 收费预告 + 早鸟价；收集 10 个付费意向 | 付费意愿验证 |
| W11–12 | 转付费；未付费降级到 Pool | 30–50% 转化 |

### 8.3 让中介「不得不用」的 5 个钩子

1. **发布即生成个人站 + 分享卡片**（30 秒，省他做图时间）
2. **每日新货**（怕错过好盘）
3. **询盘通知**（有人问 = 有生意）
4. **排行榜/贡献榜**（面子）
5. **合作成交记录**（分佣有据）

### 8.4 失败信号（要早停/转向）

- 4 周后日活 < 15%
- 池内 30 天无一条询盘
- 付费意向 < 10 人
→ 说明「池」没价值，先收缩回「个人工具 + 计算器」，别硬推网络。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| :--- | :--- | :--- |
| **飞单**（绕过平台私下成交） | 网络信任崩塌 | 归因留痕 + 合作规则 + 显示货源 + 平台不碰钱但记录 |

## 11. 需要你拍板的 6 件事

| # | 问题 | 选项 | 我的建议 |
