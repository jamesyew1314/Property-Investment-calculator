# PropNet 平台方案 v2 — 官网化 + 可验收版

> 2026-10-27 · 在 v1 基础上优化，**用于验收**  
> 变更重点：① 把 kwongthye.com 主页改造成平台官网（公司内容下沉到 `/about`）；② 计算器永久免费、只对平台收费；③ 定价从 3 档简化为「免费 / 个人 / 团队」；④ 工期改为「官网先行」；⑤ 增加逐条可测的验收标准。

---

## 0. 先回答：能不能把公司主页直接做成平台官网？

**能，而且应该。** 但要「换叙事，不换域名」。

### 为什么应该

| 理由 | 说明 |
| :--- | :--- |
| 信任背书 | 中介加入一个陌生平台会犹豫；挂在自己公司域名 + SSM/REN + 真实地址下，信任成本最低 |
| SEO 已有基础 | kwongthye.com 已收录、有证书、有内容；新域名要从 0 开始 |
| 成本 | 不买域名、不做新站、不重复维护 |
| 流量闭环 | 官网吸引买家 → 买家询盘 → 中介看到价值 → 愿意付费 |

### 要注意的三件事

1. **公司介绍不能丢**：现在首页的「关于/业务/科技/创办人」整体移到 `/about`，导航保留入口。公司是背书，平台是产品。
2. **SEO 会短期波动**：首页主题从「公司介绍」变成「房源平台」，原有品牌词排名会重新计算；对策是 `/about` 保留品牌词、内链、JSON-LD，2–4 周恢复。
3. **产品名要中性**：如果以后要卖给别的团队（EAG 等），平台不能叫「光泰内部系统」。建议产品名 **PropNet**，署名「by KWONG THYE」，对外扩张时可平移到 `propnet.my`。

> 一句话：**kwongthye.com = 平台官网 + 公司背书；PropNet = 产品名；Andy 的个人品牌 = 平台上的第一个个人站样板。**

## 2. 品牌与域名架构

### 2.1 结构

```
kwongthye.com                    ← 平台官网（新）
├── /                            首页：搜索 + 精选房源 + 给中介的价值
├── /properties                  房源池（公开部分；完整筛选需登录）
├── /properties/KT-0001          房源详情（SEO 页，联系方式脱敏）
├── /areas/sutera-utama          区域页（SEO，按新山 8 个区）
├── /agents                      中介目录
├── /a/andy-lau                  个人站（每个中介一个）
├── /join                        给中介：介绍 + 价格 + 注册
├── /about                       公司介绍（原首页内容搬到这里）
├── /pricing                     价格（计算器免费 + 平台三档）
├── /privacy /terms /pdpa        法务
├── /app                         个人工作台（登录后）
├── /library                     内部资料库（保持 noindex，仅公司用）
└── calc.kwongthye.com           投资计算器（不变，免费）
```

### 2.2 为什么个人站用路径不用子域

| 方案 | 优点 | 缺点 |
| :--- | :--- | :--- |
| `/a/andy-lau` ✅ | 不用泛域名证书；权重集中；上线快 | URL 稍长 |
| `andy.kwongthye.com` | 看起来更「个人」 | 要泛域名证书；每个子域要单独收录；权重分散 |

先用路径；等某个头部中介要独立品牌，再给他自定义域名（高级档卖点）。

### 2.3 URL 与 SEO 迁移清单

- `/` 改为平台首页；原公司内容 → `/about`（标题保留「KWONG THYE 光泰」）
- 现有锚点（`#about` 等）不 301，靠导航与内链引导；`/about` 首屏放公司关键词
- `sitemap.xml` 自动生成：静态页 + 房源 + 区域 + 中介
- 结构化数据：首页 `Organization` + `WebSite`（SearchAction）；房源页 `RealEstateListing`；个人站 `Person` + `RealEstateAgent`
- `robots.txt`：`/app` `/library` 禁止抓取；房源详情允许
- 英文：第一期沿用 JS 切换（和现在一致）；第二期关键页做 `/en/...` 静态化（Google 只认一种语言时会影响英文流量）

## 4. 产品结构（沿用 v1，补 /app 与 /library 关系）

```
公开层    /  /properties  /areas  /agents  /a/:slug  /about  /join
                 ▲ 发布（公开 or 仅池内）
工作台    /app      我的房源 · 我的 WTB · 计算器入口 · 分享 · 询盘 · 数据
内部层    /library  公司资料库（现有，仅管理员，noindex）
```

- `/app` 是**中介自己**的工作台（Pro/团队）。

- 两者共用一套表：`lib_properties` 加 `tenant_id` 后，`/app` 只看自己的，`/library` 看全部。

## 5. 定价 v2（计算器免费，只收平台）

| 档位 | 价格 | 给谁 | 核心权益 |
| :--- | ---: | :--- | :--- |
| **计算器** | **永久免费** | 所有人 | 3 Part 计算、PDF、对比、分享（云保存限 3 个方案） |
| **Pool 免费** | RM 0 | 观望 / 兼职 | 看池 + 发 **5 条**在售 + 基础资料；无个人库、无个人站、无导出 |
| **Pro 个人** | **RM 89/月**（年付 RM 890） | 全职中介（主力） | 无限房源 + WTB + 个人站 + 图片卡片 + 询盘 + 数据 + 导出 200 条/月 |
| **Agency 团队** | **RM 299/月（5 席）**，加席 RM 55 | 小团队 | Pro 全部 + 团队看板 + 品牌 + 分配 + 无限导出 |
| **早鸟** | **RM 59/月 × 12 个月**（前 80 名） | 内测团队 | 同 Pro；到期恢复 89 |

### 为什么是 89 而不是 69

- 官网会带来**买家自然流量**，中介拿到的是「客」，不只是「软件」。
- 一单佣金 RM 5,000–20,000，RM 89 ≈ 0.5%–1.8%，心理门槛仍低。
- 早鸟 59 让首批不吃亏，也不至于把长期价格锚死。

### 收入模型（含成本 RM 5,100/月：基础设施 300 + 人力 4,800）

| 场景 | 付费席 / 团队 | MRR | 净 |
| :--- | :--- | ---: | ---: |
| 只覆盖成本 | 57 席 Pro | 5,073 | ≈ 0 |
| 6 个月目标 | 40 Pro + 4 团队 | 3,560 + 1,196 = 4,756 | −344 |
| 12 个月目标 | 80 Pro + 8 团队 | 7,120 + 2,392 = 9,512 | **+4,412** |
| 对外复制 | 200 Pro + 20 团队 | 17,800 + 5,980 = 23,780 | **+18,680** |

> 结论不变：**内部 80 人做到 80% 付费才刚有利润；真正的生意是复制到别的团队。**

## 6. 核心流程（验收时按这 5 条走）

### 流程 A：中介发一条房源（目标 90 秒）

登录 `/app` → 新增房源 → 选楼盘（自动带区域/房型）→ 填单位/面积/价格 → 传 3 张图 → 选「公开到官网 + 进池」→ 发布
→ 系统同时生成：个人站页面、官网房源页、WhatsApp 卡片、池内条目。

### 流程 B：同行在池里找到它

`/properties` 搜索「Sutera Utama 3 房 80 万以下」→ 卡片显示「货源：Andy · REN 32839」→ 点「我要带客看房」→ 填客户（脱敏）→ 货源方 1 分钟内收到邮件/站内通知。

### 流程 C：官网带来自然客源

Google 搜「Sutera Utama 公寓 出售」→ `/properties/KT-0001` → 「联系货源中介」→ 留电话 → 进该中介的询盘列表（归因到房源）。

### 流程 D：WTB 配对

中介录买家需求（预算/区域/房型/时间）→ 系统匹配池内房源 → 一键把 3 套发给客户（生成对比卡片）。

### 流程 E：成交与留痕

带看完成 → 登记成交 → 房源状态自动变已售 → 审计记录（谁、何时、哪条盘）→ 合作成交可登记分成比例（平台只记录，不碰钱）。
