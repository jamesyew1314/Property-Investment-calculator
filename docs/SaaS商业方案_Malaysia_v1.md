# 马来西亚房产中介 SaaS 商业方案（v1 · 2026-10）

> 对象：全马房地产中介（REN）· 模式：垂直订阅 · 现状：单页计算器（web/）
> 说明：文中市场规模、价格、转化率为**估算区间**，需用 10–15 个中介访谈验证后再定稿。

---

## 0. 结论先行

1. **只卖"计算器"没有商业价值**：PropertyGuru/iProperty/银行/律师楼都有免费计算器，Excel 模板到处是，复制成本为零。
2. **升级成"中介的成交工具"才有付费理由**：单子分析 → 品牌化客户提案 → 分享留资 → 客户/佣金管理。付费的不是"算得准"，是"帮我成交、帮我省时间、让我显得专业"。
3. **垂直订阅可行，但天花板有限**：全马活跃中介约 1.5–2 万人，3 年做到 600–1,500 付费，个人版 ARR 约 **RM 36 万–90 万**；加上团队版与转介收入可到 **RM 150–200 万/年**。这是一个精益团队（3–6 人）能赚钱的生意，但不是 VC 级故事。
4. **做大只有三条路**：① 团队/代理公司版（按席位+白标）② 交易转介收入（贷款/律师/估价/装修）③ 出海（新加坡/泰国/越南）。单靠"中介订阅费"上限就在 RM 200 万左右。
5. **建议路径**：免费工具获客 → 付费核心（提案+分享留资）→ CRM/佣金留存 → 数据+AI 护城河 → 转介收入提 ARPU。

## 1. 市场与用户

### 1.1 规模（估算，需核实）
| 指标 | 估算 | 依据/备注 |
| :--- | ---: | :--- |
| 注册 REN（房产谈判员） | 3–4 万 | BOVAEA 制度下历年注册累计；MIEA/BOVAEP 文件提到 REN 事务与更新（见参考） |
| 活跃中介 | 1.5–2 万 | 行业经验值：注册多、全职少，年流失 30–40% |
| 代理公司（agency） | 2,000+ | 多数 5–50 人 |
| 可付费人群（SAM） | 6,000–9,000 | 活跃 × 愿付费 30–40% |

### 1.2 用户画像
- 80% 是个人或 5 人以下小团队，收入不稳定，手机为主，WhatsApp 办公。
- 语言：BM（大众市场）、EN（商业/高端）、中文（华人市场）——**BM 是放量关键**。
- 他们已经在付的钱：PropertyGuru/iProperty 的 lead 套餐（数百到数千 RM/月）、名片/传单、培训课程、油费。
- 对工具的心理价位：能带来成交的，RM 50–150/月可接受；"只是计算器"的，免费。

### 1.3 痛点排序（待访谈验证）
1. 客户问"这个买得过吗？"——需要 1 分钟出专业分析/提案（现在靠 Excel + 截图 + 口算）。
2. 佣金/co-broke/团队抽成/开票混乱（WhatsApp + Excel 记账）。
3. 客户跟进无系统，忘记跟、重复跟、离职带走客户。
4. 投资客要 yield/现金流/RPGT/出租管理。
5. 没有品牌感：发给客户的 PDF 像 Excel，不像专业顾问。

### 1.4 竞品格局
| 类型 | 代表 | 强项 | 空白 |
| :--- | :--- | :--- | :--- |
| 房源门户 | PropertyGuru、iProperty、Mudah、EdgeProp | 流量、lead、基础计算器 | 不做深度成交分析、不做客户提案闭环 |
| 数据 | Brickz、DataSense 类 | 成交价、区域数据 | 不解决"怎么说服客户" |
| 通用工具 | Excel、银行/律师计算器 | 免费 | 不品牌化、不沉淀客户、不管理单子 |
| CRM | 通用 CRM/表格 | 功能全 | 不垂直、不懂佣金/co-broke/RPGT |

**空白点 = "成交级计算 + 品牌化客户交付 + 单子/佣金管理"，垂直、轻、便宜、三语、手机优先。**

## 2. 商业价值判断

### 2.1 TAM / SAM / SOM
- **TAM（纯订阅）**：30,000 × RM 600/年 = **RM 1,800 万/年**；含团队/白标可到 RM 3,000–4,000 万。
- **SAM**：6,000–9,000 人 × RM 600 = **RM 360–540 万/年**。
- **SOM（3 年 2–5% 渗透）**：600–1,500 付费 → **RM 36–90 万 ARR**（个人版）；团队版+转介 → **RM 150–200 万**。

### 2.2 单位经济（个人版，估算）
| 项 | 数值 |
| :--- | ---: |
| ARPU | RM 49/月 ≈ RM 588/年 |
| 毛利 | 85–90%（云成本 < RM 0.3/用户/月） |
| CAC | RM 60–150（内容+社群+BD） |
| 年流失 | 30–40% → 平均生命周期 2.5–3 年 |
| LTV | RM 1,200–1,800 |
| LTV/CAC | 8–20（内容驱动时更优） |
| 盈亏平衡 | 约 250–400 付费用户覆盖 1 开发 + 1 增长 |

### 2.3 判断
- ✅ 值得做：现金流生意，先发优势在"垂直深度 + 本地语言 + 客户交付闭环"。
- ⚠️ 别高估：订阅费天花板 RM 200 万级；要靠团队版/转介/出海突破。
- ❌ 别做：房源平台、全功能 CRM、电子签、AVM 估价（资源不够、合规重、打不过现有玩家）。

## 3. 产品路线：按"付费理由"排序

### P0（0–2 月）能收钱的最小闭环
1. **账号 + 云端单子**：多设备、手机优先、断网可算（PWA）。
2. **品牌化提案**：上传 logo/头像/电话/公司，一键生成 PDF/图片/WhatsApp 文案（现有打印 CSS 可直接复用）。
3. **分享链接 + 留资**：客户打开只读提案页，记录"看了哪页、停留多久、留电话"→ **线索回流，这是杀手功能**。
4. **4 套模板**：自住 / 投资出租 / 转售 / 出租管理。
5. **三语**：BM / EN / 中文（现有 i18n 架构直接扩）。
6. **收款 + e-Invoice**：FPX/Billplz（本地）+ Stripe（海外）；接 LHDN MyInvois（2025 起企业强制，做好是壁垒）。

### P1（2–5 月）留存
7. **客户 & 单子 CRM**：阶段（看房→贷款→签约→成交）、提醒、WhatsApp 一键跟。
8. **佣金管理**：成交额、co-broke 分账、团队抽成、开票、SST 8%。
9. **对比模式**：2–3 个单位并排比 yield/现金流/ROI/RPGT。
10. **贷款资格**：DSR、月供承受力、银行利率表（人工维护即可，不必接 API）。
11. **出租模块**：租约到期提醒、租金收据、年度对账（投资客刚需，续费理由强）。

### P2（5–10 月）护城河 / ARPU
12. **数据**：区域成交/租金参考、银行利率、律师费基准（与估价师/开发商/数据商合作或自采）。
13. **AI 助手**：自然语言生成提案叙事、客户问答、自动摘要（必须加"估算/不构成建议"护栏）。
14. **团队版**：席位、统一模板、leader 看板（活跃/成单）、招募素材。
15. **转介收入**：贷款（bank panel）、律师、估价、装修、保险——按成交分成。
16. **白标**：代理公司品牌版（RM 500–2,000/月）。

### 明确不做（12 个月内）
房源 listing、全功能 CRM、电子签、AVM 自动估价、自己放贷。

## 5. GTM：全马几万中介怎么打

1. **种子期（0–90 天）**：50 个种子用户（老板/朋友的代理网络 + FB 群 + 小红书/TikTok 房产内容），每周访谈 5 个，目标是"每周至少有 1 个用户靠提案成交"。
2. **内容引擎**：免费工具页（RPGT / 印花税 / 贷款资格 / 租金回报 / 佣金计算）做 SEO（BM+EN+中文），每页 CTA 注册。每篇内容 = 一个搜索需求。
3. **社群**：FB REN 群、Telegram/WhatsApp 群，发"案例拆解 + 免费模板"，不硬广。
4. **培训/协会**：REN 培训讲师、MIEA/州属公会、代理公司老板——讲师分成 20–30%，他们需要给学员/团队工具。
5. **代理公司 BD**：先攻 20–200 人的中型公司（老板为留存付费），团队版/白标。
6. **病毒循环**：客户提案页底部"Powered by XXX · 由 XXX 生成" → 同行看到 → 注册。
7. **KPI**：注册→48h 内首个提案 >50%；免费→付费 8–12%；月流失 <4%；NPS >40；付费用户月均发提案 ≥8 份（留存先行指标）。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
| :--- | :--- | :--- |
| 免费替代 / 门户跟进 | 付费意愿低 | 速度 + 垂直深度 + 交付闭环 + 本地语言；把价值锚在"成交" |

| 被复制 | 价格战 | 数据、转介网络、团队锁定、品牌 |

## 8. 技术架构（务实版）

- 前端：现有 static → Next.js（或原生 + API），PWA，手机优先。
- 后端：Supabase（Postgres + Auth + RLS + Storage）/ 边缘函数。
- PDF：Playwright 服务端渲染（现有打印 CSS 直接复用）。
- 支付：Billplz/FPX + Stripe；e-Invoice：MyInvois API。
- 分析：PostHog/GA4，关键事件：建单子、发提案、客户打开、留资、成交。
- 数据模型：users / orgs / deals / scenarios / properties / clients / proposals / commissions / events。
- 成本：1,000 用户 < RM 300/月（Supabase + 存储 + PDF 渲染）。

## 9. 需要老板拍板的 5 件事

1. **定位**：只做计算+提案工具，还是做"中介成交操作系统"？（后者才值钱）
2. **价格锚**：RM 49（走量、兼职也买）还是 RM 79（筛全职专业用户）？
3. **转介收入**：做不做贷款/律师/装修转介？（影响品牌信任与合规）
4. **团队**：自建 1 开发 + 1 增长，还是外包 MVP 先验证？
5. **12 个月目标**：RM 30 万 ARR（保守、精益）还是 RM 100 万 ARR（必须团队版+转介）？

## 10. 如果一定要碰这四个"重产品"，怎么赢

> 先定"赢"的标准：不是在功能上超过对手，而是在**某个细分人群里成为默认选择**。四个产品各自有完全不同的护城河，打法不能混。

### 10.1 房源 Listing（对手：PropertyGuru、iProperty、Mudah、EdgeProp）

**对手的护城河**：双边网络（买家流量 ↔ 房源库存）、SEO 十几年积累、中介预算已被锁定、消费者心智。

**正面打为什么输**：买流量 + 买库存 + 买品牌，至少 RM 1,000 万级/年、3–5 年，且没有差异化理由让买家换站。

**能赢的切口（选一个，不要全做）**

| 切口 | 为什么能赢 | 最小验证 | 成本/时间 |
| :--- | :--- | :--- | :--- |
| **Co-broke 交换所**（中介对中介） | 现在 co-broke 靠 WhatsApp 群，信息散、真假难辨、分佣扯皮；做"已验证房源 + 分佣约定 + 成交记录" | 1 个城市 300–500 个活跃中介，月成交 50 单 | RM 15–40 万 / 6–9 月 |
| **细分品类**：拍卖/lelong、新盘、工业/商业、纯租赁 | 门户是"大而全"，细分数据与流程更专业（拍卖要查银行、产权、空置） | 单品类月 100 条有效盘 | RM 10–20 万 / 3–6 月 |
| **B2B2C 白标**：给开发商销售厅/代理公司做品牌盘源页 | 他们需要自己的盘源站 + 客户分析，不愿被门户抽成 | 2–3 个开发商/代理公司签约 | RM 20–50 万 / 6 月 |
| **"带分析的房源"** | 每条房源自带 ROI/现金流/RPGT 分析 + 一键提案——门户做不到 | 用现有计算器生成 50 条样板 | 复用现有代码 / 1–2 月 |

**结论**：不要做"另一个门户"。做 **co-broke 交换所** 或 **带成交分析的细分盘源**，把 listing 变成"成交流水线"的入口，而不是流量生意。

### 10.2 全功能 CRM（对手：HubSpot/Zoho/Salesforce + 各类中介自建 Excel/WhatsApp）

**对手的护城河**：功能广度、集成生态、品牌信任、企业采购流程。

**正面打为什么输**：功能军备竞赛永远追不上；通用 CRM 的"录入"中介根本不做（这是 CRM 在中介行业失败的第一原因）。

**能赢的切口**

| 切口 | 为什么能赢 | 最小验证 |
| :--- | :--- | :--- |
| **零录入 + WhatsApp 原生** | 中介活在 WhatsApp；从聊天/语音自动提取客户需求、自动建跟进，30 秒完成 | 20 个中介愿意每天用 |
| **垂直账本**：佣金/co-broke/团队抽成/SST 开票 | 通用 CRM 没有这些，中介用 Excel 算到吵架 | 10 个团队长试用 |
| **移动优先 + 离线** | 中介在工地/带看现场，网络差 | 现场可用率 >95% |
| **团队/代理公司层**：看板、招募、培训、分账 | 老板为"留人 + 抽成透明"付费，单价高 | 2 家公司试点 |

**结论**：赢不了"全功能"，但能赢"中介专属 + WhatsApp 原生 + 佣金账本"。定价 RM 49–99/月，团队版 RM 199–499/月。建 v1 约 RM 20–50 万、4–6 个月。

### 10.3 电子签（对手：DocuSign/Adobe + 本地 CA 与律所流程）

**对手的护城河**：品牌信任、法律认可、企业 IT 采购。

**先说清合规**：马来西亚《2006 年电子商务法》《1997 年数字签名法》；简单电子签可用于 booking form、LOI、租约、co-broke 协议；**SPA 仍须律师办理 + 盖章（stamping）**，电子签替代不了律师与印花税。

**能赢的切口**

| 切口 | 为什么能赢 |
| :--- | :--- |
| **不卖 e-sign，卖"成交文件包"** | booking form / LOI / 租约 / co-broke / 佣金发票，全部预填（从计算器带数据），一键签 |
| **接本地持牌 CA/签名 API，不自建密码学** | 省 12–18 个月合规与研发，按份付费（RM 1–3/份） |
| **与律所/开发商销售厅绑定** | 他们一天几十份 booking，痛点是"快 + 可追溯"，不是"签名技术" |
| **免费作为留存功能** | 不单独收费，作为 Pro 套餐的一部分，提高续费 |

**结论**：不要做独立电子签产品。做"文件包 + 合作方签名能力"，把它变成成交闭环的一环。

### 10.4 AVM 自动估价（对手：Brickz、DataSense、银行估价师、持牌估值师）

**对手的护城河**：数据（JPPH 成交、银行内部、估值师网络）、准确率、法律责任。

**先说清合规**：BOVAEA 框架下，"估值（valuation）"是持牌估值师的法定业务；创业公司只能做"**参考价/区间估算（indicative estimate）**"，不能出具估值报告。

**能赢的切口**

| 切口 | 为什么能赢 | 难点 |
| :--- | :--- | :--- |
| **不做 AVM 产品，做"分析里的 comps"** | 在提案里给"同区近期成交 3–5 条 + 参考区间"，客户立刻觉得专业 | 数据源（JPPH 滞后 6–12 月） |
| **垂直品类做到最准** | 只做一个品类（如 KLCC 公寓 / 柔佛排屋 / 拍卖盘），MAPE 做到 <10%，比通用 AVM 准 | 需要 1–2 年数据积累 |
| **中介贡献数据** | 用免费工具换"实际成交价/租金"上报，形成独家数据 | 激励机制 + 去重校验 |
| **B2B 白牌**：给估值师/银行/开发商做内部工具 | 他们缺工程能力，你有 | 销售周期长 |

**结论**：12 个月内不要做通用 AVM。把它做成"提案里的参考价 + 数据飞轮"，先积累 2–3 万条真实成交/租金，再谈 AVM。

## 11. 四件事的组合打法（真正的护城河）

单做任何一个都会被现有玩家压住；串起来才有壁垒：

```
房源（co-broke/细分盘源）
   ↓ 一键生成
成交分析（现有计算器）
   ↓
品牌提案 + 分享留资（P0）
   ↓
客户/单子 CRM + 佣金账本（P1）
   ↓
成交文件包 + 电子签（合作方）
   ↓
成交数据回流 → comps / 参考价（P2）
```

**护城河 = 中介贡献的真实成交/租金数据 + 日常 workflow 锁定 + 团队/代理公司分销。** 门户有流量但没有"成交闭环数据"；通用 CRM 有流程但不懂房产；这就是你的位置。

## 12. 优先级与资源（建议）

| 阶段 | 做什么 | 不做什么 | 预算（估） |
| :--- | :--- | :--- | ---: |
| 0–3 月 | 提案 + 分享留资 + 三语 + 支付 | listing / AVM / 电子签 | RM 5–10 万 |
| 3–6 月 | CRM-lite + 佣金账本 + WhatsApp | 全功能 CRM | RM 15–30 万 |
| 6–12 月 | 一个城市的 co-broke 交换所（邀请制） | 全国门户 | RM 15–40 万 |
| 12–18 月 | 文件包 + 合作方电子签；comps 数据 | 自建 CA / 通用 AVM | RM 10–25 万 |
| 18–24 月 | 参考价区间 + 估值师合作 + 白标 | 银行级 AVM | RM 20–50 万 |

**验收/止损线**：co-broke 交换所 6 个月内月成交 <20 单 → 停；CRM 激活率（每周活跃/注册）<25% → 回炉；参考价覆盖 <500 个小区 → 不对外叫 AVM。
