## 8. 备份与恢复

**手动备份：**

```bash
/srv/fangchan/backups/backup.sh
ls -lh /srv/fangchan/backups/
```

**恢复（演练步骤）：**

```bash
# 1) 停 API（避免写入）
systemctl stop fangchan-api

# 2) 新建临时库恢复
sudo -u postgres createdb fangchan_restore
sudo -u postgres pg_restore -d fangchan_restore /srv/fangchan/backups/fangchan-2026-10-24.dump

# 3) 核对数据
sudo -u postgres psql -d fangchan_restore -c "select count(*) from users;"

# 4) 如需替换正式库（谨慎）
systemctl start fangchan-api
```

> 目前备份仅存本机，**尚未做异地备份**；建议后续上传阿里云 OSS。

## 10. 安全设置

### 10.0 安全响应头（nginx，2026-10-25 起）

| 头 | 值 | 作用 |
| :--- | :--- | :--- |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` | 强制 HTTPS（**preload 未提交**，需要时可自行去 hstspreload.org 申请） |
| `Content-Security-Policy` | `default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self'; frame-ancestors 'self'; base-uri 'self'; form-action 'self'; object-src 'none'` | 禁止外部脚本/样式/图片；页面是单文件内联写法，所以保留 `unsafe-inline` |
| `Permissions-Policy` | `geolocation=(), microphone=(), camera=(), payment=()` | 关闭不需要的浏览器能力 |
| `X-Content-Type-Options` / `X-Frame-Options` / `Referrer-Policy` | nosniff / SAMEORIGIN / strict-origin-when-cross-origin | 基础加固 |

> 以后接 GA4 时，CSP 需要加：`script-src ... https://www.googletagmanager.com`、`connect-src ... https://www.google-analytics.com`、`img-src ... https://www.google-analytics.com`。



- UFW：仅开放 **22 / 80 / 443**
- SSH：**禁用密码登录**，仅 root 密钥（`PasswordAuthentication no`）
- fail2ban：启用（SSH 暴力破解防护）
- 自动安全更新：unattended-upgrades
- API 仅监听 `127.0.0.1:3000`，不直接暴露
- PostgreSQL 仅监听本机
- 会话 Cookie：`HttpOnly + Secure + SameSite`
- 后台：独立密码 + 邮箱验证码；`/admin` 已 noindex + robots 屏蔽
- 速率限制：登录 5/分钟、注册 5/分钟、忘记密码 5/15 分钟、联系表单 3/10 分钟

### 16.3 异地备份（开启步骤，待完成）

1. OSS 控制台建 Bucket（同区域 `oss-ap-southeast-5`，读写权限「私有」）
2. RAM 用户只授权该 Bucket 的 `PutObject/GetObject`，生成 AccessKey
3. 服务器装 ossutil 并配置：`ossutil config -e oss-ap-southeast-5.aliyuncs.com -i <AK> -k <SK>`
4. 写配置：`echo "OSS_BUCKET=kwongthye-backup" > /etc/fangchan-offsite.conf`

> **加密已默认开启**：脚本检测到 `/root/.backup-key`（AES-256，pbkdf2，20 万轮）就加密后再上传，
> 上传的是 `fangchan-YYYY-MM-DD.dump.enc` + 同名 `.sha256`。
> **这把钥匙丢了就永远解不开**——请另存一份离线（1Password / 保险箱 / 打印）。
> 解密恢复：`openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -in x.dump.enc -out x.dump -pass file:/root/.backup-key`
> 已验证：解密后与原文逐字节一致，且能正常 `pg_restore` 出 15 张表。
5. 加 cron：`40 2 * * * root /srv/fangchan/ops/offsite-backup.sh >> /srv/fangchan/logs/offsite.log 2>&1`
6. 打开监控里的 OSS 检查（脚本已内置：配置存在才检查，超过 26 小时未上传即告警）

## 16.5 外部监控（UptimeRobot，2 分钟，需要你的账号）

**为什么必须做**：现在的 `monitor.js` 是「服务器自己查自己」——**整台 ECS 挂掉或断网时，它发不出任何告警**。
外部探针从公网定时访问你的站点，超时就发短信/邮件，这才是真正的宕机告警。

1. 注册 https://uptimerobot.com （免费版 50 个监控、5 分钟间隔）
2. Add New Monitor：
   | 项目 | 值 |
   | :--- | :--- |
   | Monitor Type | HTTPS |
   | Friendly Name | kwongthye.com |
   | URL | https://kwongthye.com/api/health |
   | Monitoring Interval | 5 minutes |
   | Alert Contacts | 你的邮箱 + 手机（可选 SMS） |
3. 建议再加一个关键字监控（Keyword）：
   - URL `https://kwongthye.com/`，keyword `KWONG THYE`（防止页面 200 但内容坏了）
4. 再加一个 `https://kwongthye.com/calc/`（计算器是核心功能）
5. 把告警邮箱设为和心跳邮件同一个（`andylau.theroof@gmail.com`）

**收到「心跳邮件」= 服务器活着**：`/srv/fangchan/ops/heartbeat.js` 每天 08:00 发一封运营小报，
如果连续几天没收到，也要当成故障处理。
